# Releasing and publishing

Games ship as Arch packages. There are three channels, from quickest to most
official:

| Channel | Install line | Needs |
|---|---|---|
| `install.sh` (this repo) | `curl -fsSL https://raw.githubusercontent.com/MZAWeb/omagames/main/install.sh \| bash -s omadoku` | nothing — builds from `main` |
| Omarchy Package Repository (OPR) | `omarchy pkg add omadoku` | a tagged release + a PR to [omacom/omarchy-pkgs](https://github.com/omacom/omarchy-pkgs) |
| AUR | `omarchy pkg aur add omadoku` | an AUR account (not used for now) |

## Two PKGBUILD flavours

- `games/<game>/pkgbuild/PKGBUILD` — **development**: builds from the checkout
  (`$startdir/../../..`). Used by `bin/install`, `install.sh` and CI's
  packaging job. It carries the metadata (`pkgdesc`, `depends`, licenses…).
- `packaging/opr/<game>/` — **release**: generated by `bin/opr-pkgbuilds` from
  the development PKGBUILD's metadata, but building from the GitHub tarball
  of tag `v<version>` (single sha256), exactly like omacalc's package in the
  OPR. Includes `<game>.install` and `.omarchy/package.json`
  (`{ "source": "local" }`).

## Cutting a release

```sh
bin/release 0.1.0
```

This bumps `pkgver` in every game's PKGBUILD, commits `Release v0.1.0`, tags
`v0.1.0`, pushes both, then runs `bin/opr-pkgbuilds 0.1.0`, which downloads the
tag's tarball to compute its checksum and writes `packaging/opr/<game>/`.
Commit that directory too.

Before tagging, you can rehearse the packaging against any commit:

```sh
bin/opr-pkgbuilds 0.1.0 --ref <sha-or-branch> --out /tmp/opr-test
cd /tmp/opr-test/omadoku && makepkg -f      # must build and produce the package
```

Never publish a `--ref` PKGBUILD; only tagged ones.

## Submitting to the OPR

1. Fork `omacom/omarchy-pkgs`, create a branch.
2. Copy `packaging/opr/<game>/` to `pkgbuilds/<game>/` in the fork (one
   directory per game; separate PRs per game are easier to review).
3. Run their validation locally if available (`bin/repo release --package <game>`
   in that repo builds it the way their CI does).
4. Open a PR titled like the existing ones ("Add omadoku, Sudoku for Omarchy"),
   linking this repo and a screenshot.

Updating later: `bin/release <new-version>`, then a PR bumping `pkgver` and
`sha256sums` in each `pkgbuilds/<game>/PKGBUILD`.
